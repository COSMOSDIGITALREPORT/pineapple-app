# 02. Complete Folder Structure

## 1. Project Directory Tree

The root workspace contains the following top-level components:

```
pineapple-app/
├── assets/                             # Global static assets and branding material
├── backend/                            # Node.js + Express + Socket.IO server
│   ├── admin/                          # Web Admin Dashboard single-page client
│   └── src/                            # Express backend source code
├── pineappleandroidboys/               # React Native Android client (Boys version)
├── pineappleandroidgirls/              # React Native Android client (Girls version)
├── pineappleios/                       # React Native iOS client (Boys version)
├── pineapplegirlsios/                  # React Native iOS client (Girls version)
└── pineappleweb/                       # Static web landing marketing page
```

---

## 2. Directory Breakdown

### 2.1 Backend (`backend/`)
* **Purpose**: Core API server and signaling controller.
* **Content Type**: Javascript source code (`src/`), static web assets (`admin/`, `public/`), database initialization script (`schema.sql`), and configurations.
* **Source of Truth?**: Yes.
* **Git Status**: Committed to Git (excluding local environment file `.env` and `node_modules`).
* **Can be regenerated?**: No, contains custom source code. Dependencies (`node_modules`) can be regenerated via `npm install` / `npm ci`.

### 2.2 Web Landing (`pineappleweb/`)
* **Purpose**: Static marketing page.
* **Content Type**: HTML document (`index.html`) and image logo files.
* **Source of Truth?**: Yes.
* **Git Status**: Committed to Git.
* **Can be regenerated?**: No.

### 2.3 Mobile App Clones (`pineappleandroidboys/`, `pineappleandroidgirls/`, `pineappleios/`, `pineapplegirlsios/`)
* **Purpose**: Four targeted mobile clients.
* **Content Type**:
  * `src/`: Custom React Native Javascript source files (screens, redux store, components, service hooks).
  * `android/` and `ios/`: Native shell wrappers that load the Metro JS bundle.
  * Config files (`package.json`, `tsconfig.json`, `app.json`, `babel.config.js`, `metro.config.js`).
* **Source of Truth?**: Yes.
* **Git Status**: Custom codebase is committed to Git. Generated folders (`node_modules`, `android/build`, native cache folders) must be ignored.
* **Can be regenerated?**: Source files cannot be regenerated. Native compilation artifacts (`android/build`, Pods) can be regenerated using compiler commands.

---

## 3. Generated & Ignored Folders (Not to be Committed)

The following folders are generated automatically and must **never** be committed to Git. They are ignored in the repository's `.gitignore` rules:

| Folder Path | Generated By | Purpose | Regenerable Command |
| :--- | :--- | :--- | :--- |
| `**/node_modules/` | `npm install` | External JavaScript package dependencies. | `npm ci` / `npm install` |
| `**/android/build/` | Gradle | Android compile outputs and temporary class files. | `.\gradlew clean` |
| `**/android/.gradle/` | Gradle | Gradle wrapper configuration cache. | Generated on build. |
| `**/ios/Pods/` | CocoaPods | iOS native dependencies. | `pod install` (macOS only) |
| `**/ios/build/` | Xcode | iOS compilation outputs. | Clean build in Xcode. |
| `backend/uploads/` | Server uploads | Temporary folder where uploaded user avatars are stored locally on development. | Automatically created on file upload. |

---

## 4. Key Files to Keep Intact

* **`backend/src/config/db.js`**: Core MySQL client.
* **`backend/.env`**: Local server environment variables (never commit).
* **`pineapple-8376c-firebase-adminsdk-fbsvc-a742b2a08a.json`**: Firebase Admin credentials file inside the root directory.
* **`**/android/app/google-services.json`**: Firebase Client Android configuration files (required for Android boot).
* **`GoogleService-Info_boys.plist`** / **`GoogleService-Info_girls.plist`**: Firebase Client iOS configuration files.
